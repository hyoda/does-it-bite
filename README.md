# does-it-bite — 검사기가 실제로 무는가

> **통과는 근거가 아니다.** 아무것도 안 보는 검사도 통과를 보고한다.
> Passing is not evidence. A check that looks at nothing also reports "pass".

CI 가 초록색이다. 그래서 무엇을 아는가?

두 가지 중 하나다 — 문제가 없거나, **검사가 문제를 못 보거나.**
통과만으로는 둘을 구별할 수 없다. 그런데 우리는 대개 앞의 것으로 읽는다.

이 저장소는 그 구별을 하는 방법과, 그 방법으로 걸러진 **돌아가는 검사기 5종**<!--N:checks-->을 담았다.

```bash
git clone https://github.com/hyoda/does-it-bite && cd does-it-bite
mutation/mutate.sh mutation/cases.tsv
```

```
── 변이 시험 · mutation/cases.tsv

  ✓  고아 탐지                          물었다
  ✓  생성기 갈림                       물었다
  ✓  문서 수치 표류                   물었다
  ✓  금지 이름 누출                   물었다

무는 검사 4 · 안 무는 검사 0 · 무효 0 · 불성립 0
✓ 시험한 검사가 전부 문다
```

의존성 없다. `python3` 와 `bash` 면 된다.

---

## 왜

몇 주째 통과하던 검사가 있었다. 변이 시험을 돌려보니
**틀린 것을 넣어도 통과했다.** 정규식이 원래 매치될 수 없는 형태를 찾고 있었고,
매치가 0건이면 위반도 0건이라 초록불이었다.

그 검사는 있는 것보다 나빴다. 없으면 불안하기라도 한데, **그건 안심시켰다.**

검사를 쓰고 나서 실패시켜 본 적이 없었던 게 원인이다.
그래서 규칙 하나를 세웠다 — **새 검사는 반드시 한 번 실패시켜 본다.**
`mutate.sh` 는 그 규칙을 손이 아니라 스크립트가 지키게 한 것이다.

전체 실패 분류와 실제 사례는 **[FAILURES.md](FAILURES.md)** 에 있다.
**6가지**<!--N:failures--> 로 나뉘고, 전부 실제로 일어난 일이며, 대부분 내가 낸 것이다.

## 변이 시험 — `mutation/mutate.sh`

검사기에게 **틀린 것을 먹여보고 무는지 본다.**

`cases.tsv` 는 탭 4칸이다:

```tsv
라벨	변이시킬_파일	python3 표현식 (s = 파일 내용)	검사 명령
고아 탐지	site/index.html	s.replace('<a href="/a/">A</a>', 'A')	checks/orphan_pages.py site
```

각 케이스마다 백업 → 변이 → 검사 실행 → 복구. 판정은 넷이다:

| 판정 | 뜻 |
|---|---|
| **물었다** | 변이 후 검사가 실패했다 — 이 검사는 살아 있다 |
| **안 물었다** | 변이했는데 통과했다 — **이 검사는 아무것도 안 보고 있다** |
| **무효** | 변이가 덮어써졌다 — 생성물을 변이시켰다 |
| **불성립** | 변이 전에 이미 실패 중이었다 — 그것부터 고친다 |

### 무효 판정이 이 스크립트의 존재 이유다

생성 파이프라인이 있는 저장소에서 `dist/index.html` 을 변이시키고 검사를 돌리면,
검사가 첫 단계에서 `dist/` 를 다시 지으며 **변이를 덮어쓴다.**
검사는 깨끗한 파일을 보고 통과를 보고한다.
그러면 우리는 "검사가 문다"고 **잘못 결론짓는다.**

실제로 이 함정에 빠졌다. 처음엔 검사기가 고장 난 줄 알았다.

`mutate.sh` 는 검사 실행 뒤 파일이 그대로인지 확인하고, 아니면 `무효` 로 판정한다.
통과로도 실패로도 세지 않는다 — **시험이 성립하지 않았기 때문이다.**

> **생성물을 변이시키는 시험은 생성 파이프라인 앞에서 무효다. 정본을 변이시켜라.**

## 검사기 5종<!--N:checks-->

전부 단독으로 돌아간다. 이 저장소를 쓰지 않고 파일 하나만 가져가도 된다.

### `checks/orphan_pages.py` — 링크 없는 페이지는 없는 페이지다

```bash
checks/orphan_pages.py dist/ --ignore 'draft/*'
```

사이트맵에 있으면 기계는 찾는다. **사람은 못 찾는다.**
그 둘을 같은 것으로 착각하면, 만들어서 배포까지 한 페이지가 아무에게도 안 닿는다.

### `checks/generator_parity.py` — 두 곳에서 짓는 같은 사실

```bash
checks/generator_parity.py api.json head.json --path 'person.sameAs[*]'
```

같은 데이터를 내는 생성기가 둘 생기면 규칙도 둘이 된다.
**한쪽만 고쳐도 아무도 알려주지 않는다.** 고친 쪽만 보고 "반영됐다"고 결론짓게 된다.

경로 문법은 필요한 만큼만 있다: `a.b`, `a[0]`, `a[*]`, `a[?type=Person]`.

### `checks/doc_drift.py` — 손으로 쓴 수치는 반드시 낡는다

```bash
checks/doc_drift.py README.md --values-cmd 'scripts/count.sh'
```

문서의 수치에 표시를 붙이면 코드가 센 값과 대조한다:

```markdown
회귀 **34항목**<!--N:verify--> 을 돌린다.
```

수치를 지우라는 게 아니다. **세는 일을 코드에 넘기고 문서는 결과만 들라는 것이다.**

### `checks/leaked_names.py` — 지워도 옆 칸이 품고 있다

```bash
checks/leaked_names.py dist/ --forbidden private.txt --allow allow.tsv
```

목록에서 항목을 지우는 것만으로는 부족하다.
설명문·URL·예제 코드·**파일명**이 그 이름을 문자열로 품고 있으면 소속이 드러난다.

예외(`allow.tsv`)는 **이유와 확인일이 필수**다. 없으면 예외로 인정하지 않는다 —
이유 없는 예외는 예외가 아니라 구멍이고, 구멍은 시간이 지나면 아무도 왜 뚫렸는지 모른다.

### `checks/idempotent_build.sh` — 두 번 돌려 같은가

```bash
checks/idempotent_build.sh 'make site' dist/
```

멱등하지 않은 빌드는 조용히 비싼 값을 치른다.
매번 diff 가 뜨니 사람이 그 diff 를 안 보게 되고,
**안 보게 된 diff 속에 진짜 변경이 섞여 들어간다.**

## 자기 저장소에 붙이기

1. 필요한 검사기를 `checks/` 로 복사한다 (파일 하나씩 독립이다)
2. `cases.tsv` 에 각각의 변이 케이스를 쓴다 — **검사기 하나에 케이스 하나**
3. CI 에 두 줄을 넣는다:

```yaml
- run: checks/orphan_pages.py dist/       # 검사가 도는가
- run: mutation/mutate.sh mutation/cases.tsv   # 그 검사가 살아 있는가
```

둘째 줄이 핵심이다. 첫 줄만 있으면 F2 로 돌아간다 —
**검사가 죽어도 초록불이 뜬다.**

## 새 검사를 쓸 때 묻는 다섯

1. **이 검사를 실패시켜 봤는가?** 안 해봤으면 검사가 아니다
2. **내가 잰 것이 재려던 것인가?** 사람용 표현이 아니라 기계 값을 읽는다
3. **같은 사실을 짓는 곳이 또 있는가?** 있으면 둘을 대조하는 검사가 따로 필요하다
4. **이 근거는 무엇을 보고 있는가?** "확인했다"는 결론이지 근거가 아니다
5. **목록을 손으로 들고 있는가?** 손으로 든 목록은 다음번에 빠진다
